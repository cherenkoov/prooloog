# Prooloog

Дэшборд проектов: мини-приложение Telegram, бот и база данных на своём сервере.

Страница дэшборда (`public/index.html`) — та же самая, что работает внутри Claude. На сервере ей помогает
небольшой адаптер (`public/shim.js`): он входит через Telegram и заменяет платформу Claude запросами к этому серверу.

## Что внутри

| Файл | Зачем |

| `src/server.js` | Веб-сервер: страница, API данных, живое обновление, вебхук Telegram |

| `src/auth.js` | Вход через Telegram Mini App, сессии, роли: владелец, координатор, редактор, зритель |
| `src/bot.js` | Бот: открыть дэшборд, вход в браузере, ответы клиентов на ревью, копии данных |
| `src/join.js`, `public/join.html`, `forms/` | Онбординг: анкета в Telegram, после которой человек привязан к проекту; приглашение с QR-кодом |
| `src/realtime.js` | Живое обновление открытых экранов |
| `src/ai.js` | Ответы Claude внутри дэшборда. Включается ключом `ANTHROPIC_API_KEY` |
| `src/session.js` | Сессии с Claude в боте и его память между сессиями |
| `src/mcp.js` | Коннектор для Claude: чтение и запись данных из чата Claude |

## Правило про ответы клиентов

Бот только сохраняет ответ клиента и привязывает его к проекту. Сам проект (задачи, вёрсты, статус)
меняется после ревью владельца в дэшборде. Сервер это правило не обходит.

Тем же ревью проходят предложения Claude (коннектор, сессия в боте): сообщение с пометкой «ждёт ревью» и списком
изменений, каждое с галочкой и строками «Было / Станет». Виды изменений: следующий шаг, статус, описание и заметки
проекта, новая задача, новая верста и перенос её даты, событие, комментарий, контакт, перенос записи
(задачи, версты, комментария, события) в другой проект. Перенос нужен, когда проект открывают команде:
личные записи владельца уходят в отдельный закрытый проект, и команда их больше не видит.

## Бот

- `/start` — открыть дэшборд; `/login` — одноразовая ссылка для входа в обычном браузере
- переслать сообщение или голосовое клиента → выбрать проект → сообщение ждёт ревью
- «от имя, проект: текст» — то же одной строкой; можно сначала «от имя, проект», потом само сообщение
- любой другой текст — во входящие или как ответ клиента
- `/invite @имя editor|viewer`, `/members`, `/remove @имя` — доступ для других людей ко всем проектам; доступ к выбранным проектам выдаётся ссылкой из окна «Доступ» (см. ниже)
- `/backup` — копия всех данных файлом; файл с подписью `/restore` — восстановить из копии
- `/ask` — сессия с Claude, `/end` — завершить её; `/memory` — что Claude запомнил, `/forget да` — стереть его память

Раз в 7 дней бот сам присылает владельцу свежую копию данных (`BACKUP_DAYS`, 0 — выключить).

OAuth-клиент (Web application) проекта Google Cloud с включённым Google Meet REST API и адресом возврата `<BASE_URL>/api/google/callback`: после входа владельца (`/google` у бота) встрече в Google Meet без ссылки создаётся своя комната |

## Перенос данных из версии в Claude

1. В дэшборде внутри Claude: кнопка «Настройки» → «Скопировать все данные».
2. В дэшборде на сервере: кнопка «Настройки» → «Загрузить копию» → вставить текст → «Заменить данные этой копией».

## Локальный запуск и проверки

Нужны Node 22 и Postgres.

```bash
npm ci
TEST_DATABASE_URL=postgres://user@127.0.0.1:5432/prooloog_test npm test   # проверки сервера
DEV_DATABASE_URL=postgres://user@127.0.0.1:5432/prooloog_dev node test/dev-server.js   # песочница на порту 18081
```

Проверки и песочница используют подставные Telegram и Claude API: настоящие запросы наружу не уходят.

## Claude: ответы, вопросы боту, коннектор

**Ответы Claude в приложении и в боте.** Нужен ключ API из консоли Anthropic. В Render: сервис `prooloog` → Environment → добавить `ANTHROPIC_API_KEY`. После этого работают «Разобрать с Claude», чат в комментариях, варианты постов и сессии с Claude в боте (раздел ниже).

**Расход.** Сервер считает каждый свой запрос к Claude: токены на вход и выход и оценку стоимости по прайсу модели (`AI_PRICE_IN`, `AI_PRICE_OUT` в долларах за миллион токенов меняют прайс). Смотреть: «Бюджет» → «Подписки» → блок Claude, или `/usage` у бота. Точная сумма остаётся в консоли Anthropic.

**Коннектор для Claude.** Команда `/connect` у бота выдаёт адрес вида `https://…/mcp/<ключ>`. В Claude: Customize → Connectors → Add custom connector, название `Prooloog`, вход «No sign-in». После этого Claude в чате читает данные дэшборда, сохраняет сообщения клиентов на ревью и синхронизирует данные со страницей внутри Claude (кнопка «Синхронизировать с сервером» в «Данных»). `/connect new` выдаёт новый адрес и отключает старый. Адрес открывает все данные: не пересылать.

## Сессии с Claude в боте и его память

Кнопка «Спросить Claude» под любым текстом или команда `/ask` открывают сессию. Пока она открыта, каждое сообщение владельца боту (и пересланное тоже) идёт Claude, а он отвечает с учётом всего разговора. Чтобы сохранить что-то как ответ клиента или во входящие, сессию сначала завершают.

- Claude работает с данными дэшборда теми же действиями, что и коннектор: читает проекты, задачи, события, вёрсты, заметки, сообщения; ставит и закрывает задачи; назначает встречи (с напоминаниями, ссылкой на созвон и ссылками для участников на нужном языке); сохраняет сообщения клиентов на ревью. Сведения проекта по словам клиента он не меняет: правило про ревью действует и здесь.
- Сессия завершается кнопкой «Завершить сессию» под ответом Claude, командой `/end` или сама после 30 минут тишины (проверка раз в минуту у работающего сервера).
- При завершении Claude пишет короткую запись в память: что решили, что сделал, что осталось. Записи лежат в коллекции `memory` (только у владельца) и подмешиваются в следующие сессии, поэтому Claude помнит договорённости. Внутри сессии можно попросить «запомни …»: это отдельная запись сразу.
- `/memory` показывает последние записи, `/forget да` стирает всю память. Память попадает в копию данных и в журнал действий.
- Каждый ответ и запись в память — платные запросы к Claude; расход виден в `/usage`. В одной сессии сервер держит последние 60 реплик.

## Напоминания о событиях и созвоны

В карточке события задаются правила «за сколько до начала» (до пяти) и ссылка на созвон: Zoom, Google Meet или любая другая. Постоянная ссылка платформы запоминается и подставляется в следующие события. Бот шлёт владельцу напоминания по правилам, а если у события есть ссылка, за 5 минут до начала присылает и её. Время считается по часовому поясу приложения; событие без времени считается начинающимся в 09:00.

«Ссылка для участника» в карточке события ведёт в бота (`https://t.me/<бот>?start=ev_…`). Участник нажимает «Старт», выбирает язык и сразу получает карточку встречи со ссылкой на созвон и кнопкой «Открыть созвон»; за 5 минут до начала ссылка приходит ещё раз. Там же он выбирает свои напоминания. Доступа к дэшборду это не даёт.

**Ссылка на созвон создаётся сама.** Если событие сохранено с платформой Zoom и пустым полем ссылки, сервер заполняет его: при заданных ключах Zoom (`ZOOM_ACCOUNT_ID`, `ZOOM_CLIENT_ID`, `ZOOM_CLIENT_SECRET`) создаёт для встречи отдельную комнату через API Zoom, без ключей подставляет постоянную ссылку Zoom из настроек. Так же это работает для встреч, которые назначает Claude (в боте и через коннектор). Для Google Meet подставляется только постоянная ссылка: комнату там можно создать лишь от имени аккаунта Google. Ключи Zoom берутся в Zoom App Marketplace: Develop → Build App → Server-to-Server OAuth, права на создание встреч; в чат и в репозиторий их не кладут, только в Environment на Render. Если время встречи потом меняется, ссылка остаётся прежней и рабочей.

**Google Meet.** Комнату создаёт Meet REST API (`POST /v2/spaces`) от имени владельца, поэтому нужен его вход в Google: `/google` у бота присылает кнопку, сервер просит одно разрешение `meetings.space.created` и хранит ключ обновления в таблице `kv` (`google.oauth`). Пока входа нет или Google отказал, берётся постоянная ссылка Meet из настроек. Если Google перестал принимать ключ (отозван, либо приложение Google осталось в режиме Testing и ключ прожил 7 дней), бот один раз пишет владельцу. `/google off` удаляет ключ. Код: `src/google.js`.

**Рассылка встречи команде.** `/announce` у бота или кнопка «Разослать команде» под сообщением о встрече отправляет название, время и ссылку в личку каждому, кто прошёл онбординг проекта этой встречи. Время встречи, назначенной голосованием, пишется в поясе голосования, остальных — в поясе приложения.

**Важно про бесплатный тариф Render.** Веб-сервис засыпает через 15 минут без обращений, и пока он спит, напоминания не уходят: проверка идёт раз в 30 секунд только у работающего сервера. Надёжно работает на платном тарифе или при внешнем «будильнике», который раз в 10 минут открывает `/healthz`.

## Доступ по ссылке-приглашению

Кнопка со значком «поделиться» справа от «Данные» и кнопка «Поделиться» в шапке проекта открывают окно «Доступ» (только у владельца).

- В окне выбираются проекты (все или отмеченные) и уровень: «Смотреть» или «Редактировать». «Создать ссылку-приглашение» выдаёт адрес вида `https://t.me/<бот>?start=inv_<токен>`.
- Ссылка одноразовая и действует 7 дней. Человек открывает её в Telegram, нажимает «Старт» и получает доступ; владельцу приходит сообщение, кто вошёл.
- Гость с выбранными проектами видит только их и записи с этим проектом (задачи, вёрсты, события, посты, заметки). Записи без проекта, каналы и чужие проекты ему не приходят ни в списках, ни в живых обновлениях. Редактор пишет только внутри своих проектов, не создаёт и не удаляет проекты и не меняет настройки.
- Бюджет, контакты, переписка, подписки, клиенты, активность и учёт Claude остаются у владельца на уровнях «Смотреть» и «Редактировать». Часть из них получает координатор, см. ниже.
- В том же окне: список людей с доступом («Написать», «Изменить», «Закрыть доступ») и приглашения, которыми ещё не воспользовались («Отозвать»). Изменение и закрытие доступа действуют сразу, в том числе на открытые страницы.
- Двойное нажатие на человека в списке открывает его карточку: существующий контакт или новый, уже заполненный именем, Telegram и проектами. «Написать» открывает чат с человеком по его имени пользователя; если имени нет, бот присылает владельцу сообщение, в котором имя человека ведёт в его профиль (`POST /api/share/members/:id/chat`). Такая же кнопка есть в самой карточке.
- Уровень у человека один на все его проекты. Если человек с доступом открывает ещё одну ссылку, списки проектов складываются, а уровень становится старшим из двух.
- Внутри Claude такого деления нет: там доступ к странице выдаётся целиком средствами самого Claude.

### Координатор проекта

Третий уровень (`manager` в таблице `members`): человек ведёт выбранные проекты вместе с владельцем.

- Назначает только владелец и только человеку, у которого доступ уже есть: окно «Доступ» → «Изменить» → «Координатор». Ссылкой координатора не сделать. У координатора всегда список проектов; без списка уровень считается «редактором».
- В своих проектах координатор видит и меняет то же, что владелец: деньги, подписки и клиентов проекта, контакты и команду, сообщения и ревью изменений, рабочие чаты (написать через бота, убрать бота), онбординг и приглашение с ответами анкет и выгрузкой, журнал действий по проекту. Коллекции перечислены в `cfg.managed`; записи режет `auth.view`.
- Карточка человека, который есть и в чужих проектах, приходит координатору без этих проектов и без заметок; при сохранении сервер оставляет их как были (`auth.cardWrite`). Удалить такую карточку координатор не может.
- Доступ: координатор создаёт ссылки «Смотреть» и «Редактировать» на свои проекты, меняет и закрывает доступ редакторам и зрителям, у которых нет чужих проектов.
- Только владелец: удалить или создать проект, назначить или снять координатора, закрыть доступ координатору, настройки, копии и синхронизация, активность, учёт и память Claude, команды владельца у бота, коннектор.
- Бот пишет координаторам проекта то же, что владельцу, о новых анкетах и о времени встречи по голосованию; человеку, которого назначили координатором, приходит сообщение.
- Уровень координатора не меняется ссылкой-приглашением, анкетой или кнопкой «Открыть в Prooloog» в чате, и проект к нему так не добавляется: уровень один на все проекты человека, поэтому новый проект координатору добавляет владелец.
- В журнале действие координатора подписано его именем.

Хранение: столбец `members.projects` (`null` — все проекты, иначе список id) и таблица `invite_links`. API: `GET /api/share`, `POST /api/share/links`, `DELETE /api/share/links/:token`, `DELETE /api/share/names/:username`, `PATCH` и `DELETE /api/share/members/:id` — всё только для владельца.

## Бот в рабочем чате

Бота можно добавить в групповой чат Telegram и привязать чат к проекту (`src/groups.js`).

- **Как добавить.** На странице проекта блок «Рабочие чаты» → «+ Добавить бота в чат» (ссылка `https://t.me/<бот>?startgroup=p_<id проекта>`: Telegram предложит выбрать группу, чат привяжется сразу). Если бота добавили в группу обычным способом, он пишет владельцу в личку и спрашивает, к какому проекту привязать. Привязать может только владелец. Пока проект не выбран, бот в чате молчит и ничего не сохраняет.
- **Что бот говорит участникам.** При привязке и каждый раз, когда он начинает сохранять больше прежнего, бот пишет в чат, что именно сохраняет и кто это видит. Молча он не записывает.
- **Сбор переписки.** Сообщения чата складываются в `messages` проекта: одна запись на чат в день (`gc<чат>-<дата>`, при переполнении или после ревью начинается следующая часть), `review: "pending"`. Голосовые и аудио дополнительно сохраняются отдельными записями с плеером (`gv…`). Проект бот не меняет: записи ждут ревью владельца, как любой ответ клиента. Режимы: все сообщения, только обращённое к боту, ничего.
- **Что видит бот.** По правилам Telegram бот в группе по умолчанию получает только команды и ответы на свои сообщения. Чтобы он видел всё, его нужно сделать администратором чата (или выключить privacy mode у @BotFather и добавить бота заново).
- **Кнопки и команды в чате.** `/project` — карточка проекта с кнопками «Задачи», «Вёрсты», «События»; `/task текст` и `/note текст` (или ответом на чужое сообщение) — предложение задачи или заметки; кнопка «Предложить задачу». Предложения приходят владельцу на ревью (`gs…`, с готовым `proposal`) и попадают в проект после подтверждения.
- **Проект в приложении.** Если владелец включил это для чата, кнопка «Открыть в Prooloog» даёт участнику чата доступ «смотреть» только к этому проекту (см. «Доступ по ссылке-приглашению»). Вышедшим из чата и посторонним доступ не выдаётся; владелец получает сообщение о каждом новом доступе и может закрыть его в окне «Доступ».
- **Напоминания.** По настройке чата бот пишет туда напоминания о событиях проекта по правилам события, ссылка на созвон приходит за 5 минут.
- **Из дэшборда.** В блоке «Рабочие чаты»: настройки чата, «Написать в чат от бота», «Убрать бота из чата». Записи чатов — коллекция `chats` (только владелец). API: `POST /api/chats/:id/post`, `POST /api/chats/:id/leave`.
- Команды владельца в самом чате: `/link` — выбрать проект заново, `/unlink` — отвязать.

## Онбординг: анкета, которая привязывает человека к проекту

Одна ссылка на весь чат. Человек открывает её в Telegram, нажимает «Старт», заполняет анкету в мини-приложении и сразу оказывается в проекте.

- `/onboard проект` у бота (или `/onboard` и выбор проекта кнопкой) выдаёт ссылку вида `https://t.me/<бот>?start=join_<токен>` и готовый текст для чата. Ссылка одна на проект и работает для любого числа людей, пока её не выключить: `/onboard off проект`.
- Анкета описана файлом в `forms/` (сейчас один: `ecochakra.json`). Шаги с `"part": "core"` — основная часть, все её обязательные вопросы проверяет сервер. Шаги с `"part": "more"` — расширенная часть: по желанию, сохраняется после каждого шага. Типы вопросов: `text`, `tel`, `email`, `url`, `area`, `one`, `many` (`max`, `other`, `lead`).
- После основной части человек получает доступ только к этому проекту с правом редактировать (как по ссылке-приглашению «Редактировать»), становится контактом проекта (`contacts/jn-<id>`, в заметках краткая выжимка анкеты), а владельцу приходит сообщение с выжимкой. Владелец может заполнить анкету сам: его доступ не меняется.
- Голосования: массив `polls` в файле анкеты. Голосовать можно после основной части (владельцу — сразу), голос можно менять, все видят, кто за что проголосовал. `/votes` у бота — итог текстом. Голосование с `"kind": "time"` — сетка часов одного дня (`date`, `opts`, `offset` и подпись пояса `zone`); если у него есть `event`, время большинства (при равенстве — более раннее) становится началом встречи `events/<event.id>` в проекте, в часовом поясе приложения. Голосование из `event.call` (Zoom / Google Meet / Discord) задаёт у встречи вид созвона и подставляет постоянную ссылку из настроек. Запись меняется только когда выбор большинства сдвинулся; название и ссылку, которые владелец поправил руками, голоса не трогают. `"closed": true` закрывает голосование.
- Ответы лежат в коллекции `joins` (`<анкета>-<id в Telegram>`): общий API `/api/db` её не отдаёт, в копию данных (`/backup`) она попадает. `/answers` присылает таблицу CSV: строка на человека.
- **Страница онбординга у проекта.** На странице проекта у владельца есть блок «Онбординг»: включить или выключить ссылку, скопировать её или готовый текст для чата, открыть окно с ответами. В окне: голосования, сводка по ответам (у каждого вопроса с вариантами видно, сколько человек что выбрали и кто именно), список заполнивших с ответами каждого и выгрузка CSV. Данные приходят отдельным API только для владельца: `GET /api/onboard/:project` (обзор), `POST` (включить ссылку), `DELETE` (выключить), `POST /api/onboard/:project/csv` (таблица в бот). Внутри Claude этого блока нет: анкеты живут на сервере.
- Личность берётся только из подписи Telegram: вне Telegram страница анкеты показывает кнопку «Открыть в Telegram».

### Приглашение: ссылка и QR-код для личных встреч

У проекта может быть вторая ссылка, отдельная от командной: приглашение. Его анкета — файл в `forms/` с `"access": "card"` (сейчас `ecochakra-club.json`).

- `/club проект` у бота присылает постоянную ссылку, QR-код картинкой и два готовых текста: участнику и мастеру. `/club off проект` выключает ссылку. В дэшборде то же самое в блоке «Онбординг» → «Приглашение»: ссылка, «QR-код и тексты», ответы.
- Кто заполнил анкету, становится контактом проекта (`contacts/jn-<id>` или карточка, найденная по @имени; повторная анкета обновляет ту же карточку). Доступа к проекту он **не получает** и в команду не попадает: после анкеты видит витрину проекта. Текст витрины — поле проекта `show` («Витрина» в форме проекта); пока оно пустое, показывается `about` из файла анкеты. Задачи, заметки и описание «Зачем» гостю не отдаются.
- Ветвление: у вопроса или шага может быть `"when": {"q": "<id вопроса>", "in": ["вариант", …]}`. Он задаётся, только если в ответе на тот вопрос есть один из вариантов; иначе ответ на него не сохраняется и обязательным он не считается (проверяет сервер). Уточняющие вопросы с `"sub"` рисуются прямо под выбранным вариантом.
- Мастер: `"master": {"q", "in", "role", "by"}` в файле анкеты. Если ответ совпал, карточка получает `master: true` (пометка «Мастер» и фильтр «Мастера» в «Контактах») и роль вида «Мастер: Цигун / тайцзи». Анкета пометку не снимает.
- Согласие: `"agree"` в файле анкеты — строка с галочкой на последнем шаге. Без `agree: true` сервер не сохраняет ни ответы, ни карточку (`no_consent`); время согласия пишется в `joins.agreed`.
- API владельца: `POST /api/onboard/:project {form: "invite"}` включает приглашение, `DELETE …?form=invite` выключает только его, `GET /api/onboard/:project/qr` отдаёт QR-код (SVG), `POST …/csv?form=invite` — таблицу ответов приглашения. `GET /api/onboard/:project` отдаёт приглашение в поле `invite`.

### Выгрузка онбординга одного проекта

Все ответы онбординга проекта одним файлом, командная анкета и приглашение вместе, в CSV или JSON.

- Дэшборд: окно ответов онбординга или приглашения → «Выгрузить CSV» / «Выгрузить JSON». В Telegram файл присылает бот в чат, в обычном браузере он сохраняется на устройство.
- Бот: `/answers проект` (CSV), `/answers json проект` (JSON). `/answers` без проекта по-прежнему присылает таблицы всех анкет.
- CSV: строка на человека и анкету; столбцы — анкета, даты, имя, Telegram, пометка «Мастер», дата согласия и все вопросы этих анкет, затем голосования. JSON: проект, по каждой анкете её вопросы с вариантами, голосования и люди с ответами, голосами и id карточки контакта.
- API владельца: `POST /api/onboard/:project/export {format: "csv" | "json", send?: true}`. С `send` файл уходит в чат владельца с ботом, без него текст файла возвращается в ответе. Выгрузка записывается в журнал.

### Команда и контакты

Кто в команде проекта, записано на карточке: `contacts.team` (список id проектов) и `rel: "Команда"`. Командная анкета ставит это при первом прохождении; дальше карточку переносит владелец кнопкой «→ В команду» / «→ В контакты» на карточке, и повторная анкета её место не меняет. Карточкам, заведённым до этого правила, сервер один раз при запуске проставляет `team` по ответам командной анкеты (`kv`: `team.oncard`). Рассылка встреч команде (`/announce`) идёт только тем, кто прошёл командную анкету.

API: `GET /api/join/:token` (анкета и название проекта), `POST /api/join/:token/me`, `/submit`, `/vote` — все три с `initData` из Telegram.

## Логи: история действий с данными

«Данные» → «Логи»: небольшое окно со своей прокруткой и кнопка «на весь экран» (с фильтром «Добавлено / Изменено / Удалено»). Строка открывает запись, о которой она.

- На сервере журнал ведёт сервер (`src/journal.js`) для всех, кто меняет данные: владелец, гости, бот, рабочие чаты, Claude через коннектор. Подписаны все, кроме владельца. Туда же попадают загрузка копии, синхронизация и изменения доступа.
- Записи копятся пару секунд и дописываются в запись дня `audit/s<ГГГГММДД>` (коллекция только для владельца, руками в неё писать нельзя). Хранится 90 дней.
- Не пишутся служебные коллекции (активность, расход, отметки удаления), перестановки в списке и изменения, которые ничего не меняют. День переписки рабочего чата — одна строка.
- Внутри Claude страница ведёт журнал сама: `audit/l<ГГГГММДД>-<устройство>`.
- Журнал не входит в копии, слияния и синхронизацию: это история конкретной копии данных.

## Языки для участников встреч

Бот говорит с участником встречи на его языке (`src/i18n.js`, сейчас русский и английский).

- В форме события, блок «Участнику встречи»: «Язык сообщений участнику». «Участник выберет сам» — ссылка `start=ev_<токен>`: бот сначала спрашивает язык и первым предлагает вероятный (по языку Telegram участника). «Русский» / «English» — ссылки `start=evru_<токен>` / `start=even_<токен>`: бот сразу пишет на этом языке, без вопроса.
- Выбор человека запоминается: следующая ссылка открывается без вопроса. Язык можно сменить кнопкой «🌐» под встречей.
- Напоминания и ссылка на созвон приходят на языке участника. Пока человек не ответил на вопрос о языке, напоминания идут на вероятном.
- Напоминание в рабочий чат идёт на языке, который задан у события, иначе на русском.
- Добавить язык: ещё один блок с теми же ключами в `src/i18n.js`.
